# Исследование библиотек для визуального редактора клиентского пути

## Проблема
Текущий редактор (`public/admin/index.html`) — это canvas-демо без полноценной работы со сценарными ветками: неудобно строить цепочки вида **вопрос → варианты ответов → следующий вопрос → ... → выбор услуг/финал**.

Нужно перейти к полноценному graph-editor UX:
- drag & drop узлов;
- визуальные порты/хэндлы для связей;
- редактирование ветки «по ответу» на ребре;
- валидация графа (потерянные ветки, циклы, недостижимые узлы, отсутствие финального RESULT);
- сериализация в backend-модель `ScenarioGraph`.

---

## Кандидаты

### 1) React Flow (`@xyflow/react`) — **рекомендуемый вариант**
**Что даёт из коробки**
- Интерактивный node-based UI: drag, zoom, pan, multi-select, add/remove nodes/edges.
- Кастомные узлы как обычные React-компоненты (удобно для QUESTION/RESULT/SERVICE_SELECTION).
- Встроенные UI-компоненты (Controls, Minimap, Background, Panel, NodeResizer).

**Плюсы для нашего кейса**
- Низкий порог входа для frontend-команды (React-first).
- Отлично подходит для сценарного конструктора с типизированными нодами и «ветвлением по ответам».
- MIT-лицензия, активное сообщество, высокая зрелость.

**Риски/ограничения**
- Требуется аккуратная архитектура состояния графа и синхронизации с backend DTO.
- Нужны дополнительные layout-утилиты для автокомпоновки крупных схем (например, dagre/elkjs).

### 2) Rete.js
**Что даёт**
- Processing-oriented framework для визуального программирования.
- Поддержка dataflow/control-flow движков, plugin-архитектура.

**Плюсы**
- Сильный вариант, если нужно не только рисование графа, но и «исполнение» графа в браузере.

**Минусы для нас сейчас**
- Чуть выше порог сложности и оверхед по экосистеме плагинов по сравнению с React Flow для чисто редакторской задачи.

### 3) AntV X6
**Что даёт**
- Мощная диаграммная библиотека с глубокой кастомизацией.

**Плюсы**
- Гибкость для enterprise-диаграмм, сложные сценарии кастомизации.

**Минусы для нас сейчас**
- Более «низкоуровневый» и тяжёлый старт, чем React Flow, если цель — быстро получить удобный редактор клиентского пути.

### 4) Cytoscape.js
**Что даёт**
- Сильная библиотека для graph theory/visualization/analysis, богатые алгоритмы.

**Плюсы**
- Отлична для аналитики и алгоритмов на графах.

**Минусы для нас сейчас**
- UX редактора бизнес-процессов (формы узлов, connection handles, authoring-flow) обычно требует больше собственной обвязки.

### 5) JointJS (OSS core / JointJS+)
**Что даёт**
- Зрелая диаграммная экосистема (Graph + Paper, shape/link модели).

**Плюсы**
- Богатые diagramming-возможности.

**Минусы для нас сейчас**
- Для ускоренной поставки часть удобных enterprise-фич может увести в коммерческий контур JointJS+.

---

## Рекомендация
Для «добить редактор» в кратчайшие сроки выбрать **React Flow** как базу v1:
1. Быстрый time-to-value для UX редактора ветвящихся диалогов.
2. Нативная модель узлов/рёбер легко мапится на `ScenarioNode`/`ScenarioEdge`.
3. Простая интеграция с текущим embedded frontend-подходом.

Rete.js держать как **кандидат v2** только если появится требование выполнять/симулировать dataflow/control-flow прямо в редакторе сверх текущей runtime-логики backend.

## Предлагаемая целевая модель графа (для UX)

### Узлы
- `QUESTION`
  - поля: `id`, `text`, `answerOptions[]`.
- `SERVICE_SELECTION`
  - поля: `id`, `text`, `serviceRefs[]`, `selectionMode`.
- `RESULT`
  - поля: `id`, `text`, `resultType`, `visitCreationSettingsRef`.

### Рёбра
- `fromNodeId`, `toNodeId`, `answerCode`.
- для перехода по умолчанию: `answerCode = "__default__"`.

### Валидации перед сохранением
- один стартовый узел;
- у каждого `QUESTION` есть хотя бы одна исходящая связь;
- `answerCode` уникален в рамках одного `fromNodeId`;
- все узлы достижимы от старта;
- есть хотя бы один путь до `RESULT`.

## Пошаговый план внедрения редактора (Phase 0)

### 0.1. Технический spike (2–3 дня)
- Поднять отдельный PoC-экран на React Flow с 3 типами узлов.
- Сделать создание/удаление узлов и связей.
- Добавить side panel для редактирования `text`, `answerCode`, service refs.

### 0.2. MVP редактора (1 спринт)
- Импорт/экспорт JSON в текущий backend-контракт.
- Валидации графа на клиенте + подсветка ошибок на канве.
- UX «быстро собрать цепочку»:
  - добавить вариант ответа;
  - протянуть связь;
  - автоматически создать следующий QUESTION.

### 0.3. Production-hardening (1 спринт)
- Undo/redo, autosave, optimistic locking.
- Версионирование сценария + diff preview перед публикацией.
- E2E тесты Playwright на ветвящиеся сценарии.
